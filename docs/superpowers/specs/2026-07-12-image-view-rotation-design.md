# PlaScan 影像查看旋转设计

## 目标

为 PlaScan 的单影像查看视图增加“向左旋转”和“向右旋转”功能。每次旋转 90 度，旋转状态按影像保存到当前项目，切换影像或重新打开项目后恢复。

旋转仅属于查看状态：不改写原始影像，不改变影像像素坐标、相机参数、特征文件、匹配文件或摄影测量计算输入。

## 范围

- 支持主工作区中的单影像 `CanvasWidget`。
- 向左和向右旋转均以 90 度为步长。
- 支持 `0`、`90`、`180`、`270` 四个规范角度。
- 在“视图”菜单和主工具栏中提供两个图标动作。
- 按影像路径在项目 UI 设置中保存角度。
- 影像底图、兴趣点、蒙版轮廓和当前场景中的其他覆盖层一起旋转。

匹配查看器、双图对比视图和 3D 相机影像平面不在本次范围内。它们使用独立的视图和同步变换协议，后续如需旋转应单独设计，避免影响匹配点坐标同步。

## 方案选择

采用 `QGraphicsView` 视图变换旋转整个场景。旋转不修改 `QImage`，也不逐个变换 `QGraphicsItem`。

未采用的方案：

- 逐个旋转图层：需要重构 `LayerRenderer` 中底图、特征点、匹配线和蒙版的父子关系，改动面大。
- 旋转解码后的像素：高分辨率影像会产生额外内存和重采样开销，并要求重新映射所有覆盖层坐标。

## 组件边界

### CanvasWidget

`CanvasWidget` 维护当前规范化角度 `_viewRotationDegrees`，提供：

- `rotateLeft()`
- `rotateRight()`
- `setViewRotationDegrees(int degrees)`
- `viewRotationDegrees() const`
- `hasDisplayImage() const`

画布同时维护单影像就绪状态。`showImage()` 开始异步加载时先清除该状态，加载成功后设置；`showMatchedPair()`、空路径和加载失败均保持未就绪。旋转动作只在单影像已成功显示时生效，避免误转匹配拼接视图。

旋转通过 `QGraphicsView` 的变换矩阵实现。操作前记录视口中心对应的场景坐标，旋转后恢复该中心，使当前观察位置不发生无意义跳动。缩放因子保持不变。

新增 `viewRotationChanged(const QString &imagePath, int degrees)` 信号。只有用户触发左转或右转时发出；加载持久化状态时不重复写设置。

影像异步加载完成后，画布按当前角度重新建立视图变换并适配场景。异步结果仍使用现有影像路径和 watcher 校验，旧影像的完成回调不能覆盖新影像角度。

`resetView()` 清除平移和额外缩放、重新适配当前场景，但保留当前影像旋转角度。

### ImageViewRotationSettings

在 `src/gui/config` 增加无 UI 依赖的配置助手，负责：

- 将任意整数规范化为 `0/90/180/270`。
- 生成规范化影像路径键；Windows 下比较时不区分大小写。
- 从 UI 设置的 `image_view_rotations` 对象读取指定影像角度。
- 更新指定影像角度；角度为 0 时删除对应条目，避免配置长期累积默认值。
- 忽略空路径、非数字值和不是 90 度倍数的旧配置。

配置结构：

```json
{
  "image_view_rotations": {
    "g:/hayabusa2/data/image_001.tif": 90,
    "g:/hayabusa2/data/image_002.tif": 270
  }
}
```

该设置沿用项目现有 `DialogSettingStore`/UI 设置文件，不进入摄影测量结果元数据，也不把项目标记为重建结果已修改。

### MainMenu 与 MainWindow

`MainMenu` 创建 `actionRotateImageLeft` 和 `actionRotateImageRight`，加入“视图”菜单，并在主工具栏中以稳定尺寸的图标按钮显示。图标使用影像轮廓和方向明确的弯曲箭头，工具提示分别为“向左旋转”和“向右旋转”。

按钮没有打开影像时禁用。打开单影像后启用；关闭项目或清空画布后禁用。动作直接调用 `CanvasWidget::rotateLeft()` 和 `CanvasWidget::rotateRight()`。

`MainWindow` 在项目 UI 设置加载时缓存 `image_view_rotations`。打开影像前先读取该影像角度并应用到 `CanvasWidget`。收到用户旋转信号后，仅更新当前影像条目并通过现有 `saveUiSetting()` 合并保存。

## 变换行为

旋转角度采用顺时针为正：

- 向右旋转：`0 -> 90 -> 180 -> 270 -> 0`
- 向左旋转：`0 -> 270 -> 180 -> 90 -> 0`

视图矩阵由当前旋转和缩放共同组成。所有场景图元使用原始影像坐标，因此特征点、蒙版和匹配覆盖层无需重算坐标，屏幕显示仍与底图对齐。

切换到另一张影像时，不继承上一张影像角度。每张影像从项目设置读取自己的角度；没有记录时使用 0 度。

## 状态与错误处理

- 没有影像时旋转函数安全返回，不修改设置。
- 影像加载失败时不启用旋转动作，也不写入角度。
- 项目 UI 设置不存在或格式错误时使用 0 度。
- 中文路径和非 ASCII 路径通过 `QString`、`QDir::cleanPath` 和现有 JSON 接口处理。
- 路径对应影像从项目移除后，残留旋转项不会影响其他影像；后续保存 0 度可清理该项。

## 测试

使用 GTest 覆盖：

1. 角度规范化和左右四次循环。
2. Windows 路径大小写及中文路径读取同一设置。
3. 0 度删除持久化条目，非 90 度配置回退为 0。
4. `CanvasWidget` 左右旋转更新视图矩阵和公开角度。
5. 四次同方向旋转回到 0 度。
6. 旋转后场景中的底图与覆盖层仍共享同一视图变换。
7. `resetView()` 保留旋转角度并重新适配场景。
8. 工具栏和“视图”菜单包含两个动作，文本、工具提示和图标正确。
9. 没有影像时动作禁用，影像加载完成后启用。
10. 切换两张影像时分别恢复各自角度。
11. 保存并重新加载项目 UI 设置后恢复旋转角度。

验证包括相关 GTest、过滤 CTest、Release GUI 构建，以及手工打开横向和纵向影像检查旋转、缩放、蒙版和兴趣点对齐。

## 非目标

- 不修改 TIFF/JPEG/PNG 文件内容或 EXIF Orientation。
- 不改变相机模型、主点、焦距、畸变参数或特征坐标。
- 不为任意角度旋转增加输入框或滑块。
- 不增加撤销历史；反方向旋转即可恢复。
- 不同步旋转双图匹配查看器。
