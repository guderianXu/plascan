# PlaScan 自适应三级深度金字塔设计

## 背景

当前 PlaScan 深度估计采用两层粗到精 PatchMatch。标准模式通常执行 `ds=4 -> ds=2`，高质量模式则可能
执行 `ds=4 -> ds=1`。后者缺少中间层，粗层错误会以最近邻方式直接放大到全分辨率；同时粗层固定使用很低
的置信阈值，精层没有根据提示覆盖率调整搜索范围，少量错误初值会扩散成块状深度、突刺、断裂和浮动表面。

Dino 与 9 张 UAV 数据的模型—影像回归测试进一步表明：深度图有效覆盖不稳定、每帧实际源视图通常只有
2–3 张、流式低内存路径会跳过全量几何一致性检查，最终网格只是放大了深度阶段的问题。

Metashape 的公开手册将深度图质量定义为不同最终分辨率档位，并提供深度过滤档位；公开 API 还允许访问
深度图的多个 level。PlaScan 不复制未公开实现，而是采用明确、可测试的三级粗到精深度估计，并保留每层
诊断产物。

## 目标

- 使用三级深度金字塔稳定大范围搜索、连续表面和高分辨率细节。
- 自动区分环拍任意 3D 与航测高度场场景，并选择不同的源视图、过滤和质量门槛。
- 父层向子层传递深度中心和不确定区间，而不是不可纠正的硬深度。
- 低内存流式模式仍执行多视几何一致性，不允许为了省内存静默降级质量。
- 在融合和网格重建前拒绝低覆盖、低支持或几何不一致的深度帧。
- 通过 Dino、UAV 9 图和模型—影像回归工具建立自动质量门槛。

## 非目标

- 不依据 Metashape 截图猜测或复制其私有算法。
- 本阶段不重写网格算法；先保证深度图和融合点云正确。
- 不为追求满幅覆盖而填充无证据区域。
- 不让三级中间图全部长期驻留内存。

## 场景自动识别

新增 `MvsSceneProfile`：

- `Auto`：默认，根据相机中心分布、光轴交汇、场景厚度和稀疏云主方向判定。
- `OrbitalObject`：环拍、近景物体、任意 3D 表面。
- `AerialTerrain`：对地航测、主要为 2.5D 高度场。
- `Custom`：用户显式覆盖高级参数。

自动判定使用以下特征：

- 相机中心 PCA 的三个特征值比例。
- 相机光轴与稀疏云中心的交汇一致性。
- 稀疏云在最佳拟合平面法向上的厚度比例。
- 相机俯视方向一致性与航带结构。

无法可靠判断时选择 `OrbitalObject`，因为它对表面方向假设更少，并在日志和 metadata 中记录判定依据。

## 三级深度估计

### Level 3：全局结构层

- 目标：确定可靠的大结构和深度区间。
- 设最终层 downsample 为 `D`，默认使用 `Level 1 = D`、`Level 2 = 2D`、`Level 3 = 4D`。
- 若某一级短边小于 160 像素，则将该级限制到短边不少于 160 像素；相邻两级 downsample 必须严格递减。
- 从共视稀疏点分位数生成初始深度区间，并按图像网格估计局部区间。
- 使用 4–8 个候选源视图；每个像素至少需要两个有效光度支持。
- 输出深度、置信度、支持视图数和初始不确定度。
- 低纹理区域可以保持无效，禁止用极低阈值制造满幅随机深度。

### Level 2：几何稳定层

- 目标：修正父层误差并恢复连续表面。
- 分辨率位于 Level 3 与最终层之间；最高质量的完整路径为 `ds=4 -> ds=2 -> ds=1`。
- 父层深度转换为 `depthCenter + depthRadius`；半径由父层置信度、局部梯度和支持视图数决定。
- 高置信父像素使用窄搜索，低置信像素扩大搜索，无父深度像素可从稀疏点或全局区间重新初始化。
- 上采样采用联合双边/边缘感知插值，不使用最近邻作为最终深度提示。
- 完成后执行邻接源视图前后向一致性检查。

### Level 1：细节恢复层

- 目标：在可靠区域恢复最终细节，不扩大错误覆盖。
- 最终分辨率由质量档位决定：最高 `ds=1`、高 `ds=2`、中 `ds=4`、低 `ds=8`、最低 `ds=16`。
- 仅在父层可靠区域和可重新验证区域运行精化。
- 使用更小的深度搜索区间、完整迭代预算和边缘感知 patch。
- 遮挡边界、反光、低纹理和多视冲突区域输出无效，不做强制补洞。

每一级都保留：

- `depth`
- `confidence`
- `support_count`
- `uncertainty`
- `valid_mask`
- `source_view_ids`
- `quality_summary`

默认只持久化 Level 1 和各层摘要；Debug 模式可保存 Level 2/3 预览与原始数据。

## 源视图策略

源视图计划从“每帧固定列表”扩展为“候选池 + 每像素有效支持”：

- 候选池仍使用共视 track、几何内点、基线角、覆盖率和序列邻接评分。
- `OrbitalObject` 优先环向相邻且基线角互补的 4–6 张影像，避免只来自同一侧。
- `AerialTerrain` 优先同航带前后影像和相邻航带影像，候选 6–8 张，至少包含跨航带支持。
- PatchMatch 光度代价只聚合实际可见且通过 NCC 门槛的视图，不要求所有候选同时支持。
- 支持数量、最佳/次佳代价间隔和视角分布共同形成置信度。

## 置信度与不确定度

替换单一 NCC 置信值，形成校准后的组合置信度：

`confidence = photometric * support * uniqueness * geometry * texture`

- `photometric`：鲁棒多视 NCC。
- `support`：有效支持视图数及其视角多样性。
- `uniqueness`：最佳与次佳深度假设的代价间隔。
- `geometry`：前后向重投影与相对深度一致性。
- `texture`：局部梯度和结构张量，防止无纹理区域得到虚高置信度。

不确定度至少包含父层分辨率误差、深度搜索宽度、代价曲线宽度和几何一致性误差。融合阶段使用不确定度加权，
而不是只根据固定置信阈值二值接受。

## 深度过滤档位

提供与使用目的对应的过滤档位，但不冒充 Metashape 内部实现：

- `Mild`：只移除极小 speckle、明显局部突刺和强几何冲突，适合 Dino 与直接深度图建模。
- `Moderate`：生产默认，增加连通域和置信度门控。
- `Aggressive`：适合平坦航测地面，移除小组件和低支持区域，不用于复杂近景物体默认值。

过滤在深度分段空间执行，连通域关系同时考虑像素邻接和相对深度差，避免把不同深度表面错误连接。

## 帧级质量门控

每帧生成以下指标：

- 内容区域内有效覆盖率。
- 支持视图数量分布。
- 置信度 P10/P50/P90。
- 前后向一致像素比例。
- 深度连通域数量与最大组件占比。
- 与稀疏点深度残差。
- 深度边缘与影像边缘一致性。

满足任一硬失败条件的帧不得进入融合：

- 内容覆盖率极低且没有稳定主组件。
- 多视一致率低于场景档位门槛。
- 深度范围集中在搜索边界，表明搜索未收敛。
- 与稀疏点先验存在系统性尺度或符号冲突。

软失败帧可降权参与相邻帧验证，但不能独立产生融合点。

## 流式多视一致性

低内存模式不再跳过一致性检查：

1. 按参考帧加载 Level 1 深度及其 source 邻接帧。
2. 执行前后向重投影、相对深度和法线一致性。
3. 写回过滤后的深度、置信度、支持数和 mask。
4. 释放该邻域并继续下一帧。

缓存使用内存预算控制的 LRU；批次只保存当前邻域。这样内存随邻域大小增长，而不是随总影像数增长。

## 配置和 UI

深度图质量改为五档：`最高 / 高 / 中 / 低 / 最低`，分别对应最终 `ds=1/2/4/8/16`。内部三级计算
由系统自动推导，不让普通用户配置每层全部细节。

高级设置新增：

- 场景类型：自动 / 环拍任意 3D / 航测地形。
- 深度过滤：轻度 / 中度 / 强力。
- 保存中间级别：默认关闭。
- 最小一致视图、最终分辨率和 CUDA 内存预算覆盖项。

深度图查看器增加 `所有级别 / Level 1 / Level 2 / Level 3 / 置信度 / 支持数 / 不确定度`，明确这是
PlaScan 的诊断视图，而不是简单复制外部产品文案。

修复现有配置语义冲突：Dialog 的预设必须写入稳定的 profile ID；后端不得把“快速”预设再次按默认
`standard` 提高到另一组参数。项目 metadata 记录最终生效的逐层配置。

## 数据与接口

扩展 `PatchMatchConfig` 或新增 `DepthPyramidConfig`：

- 最终 downsample。
- 各层 downsample、迭代数、patch、置信门槛。
- 不确定区间收缩策略。
- 场景 profile 和过滤模式。
- 最小/目标 source 数。

新增 `DepthLevelResult`，`DepthFrameResult` 持有最终层和可选中间层 metadata。工作区 manifest 增加 schema
版本和各层质量摘要；旧 manifest 只作为单层 Level 1 读取，配置签名不匹配时禁止静默复用。

## 验证

### 单元测试

- 三级分辨率推导和质量档位映射。
- 父层深度/不确定度上采样。
- 低置信父深度可被子层纠正。
- 场景自动识别：环拍与航测相机布局。
- 帧级质量门控。
- 流式一致性与内存缓存。
- Dialog profile ID 与后端最终配置一致。

### 合成测试

- 平面、斜面、深度阶跃、遮挡边界和无纹理区域。
- 比较单层、旧两层和新三级的深度 RMSE、完整率、错误覆盖率。
- CUDA 与 CPU 在容差内给出一致接受/拒绝结果。

### 实际数据硬门槛

- Dino：16/16 相机保持注册；可接受深度帧不少于 14 帧；模型最大连通组件面数占比不低于 90%；
  独立浮片面数占比低于 2%；留出视角渲染轮廓 IoU 不低于 0.80，且不能出现覆盖主体的大面积背板。
- UAV 9 图：9/9 相机保持注册；可接受深度帧不少于 8 帧；模型最大连通组件面数占比不低于 90%；
  地面主体不得退化为离散小岛；与 Metashape 局部参考点云对齐后 P50/P84/P95 距离均优于旧实现，
  在相同误差阈值下的覆盖率至少提高 20%。
- 只有 9 图通过后才运行 444 图长链测试。

每次 A/B 都保存配置、深度摘要、接触表、模型回归报告和失败帧列表，禁止只凭单张彩色预览判断完成。

## 实施顺序

1. 修复质量预设与后端配置不一致，建立三级配置和测试。
2. 实现 Level 3/2/1 结果与不确定区间传播。
3. 实现场景自动识别和场景化 source 计划。
4. 实现校准置信度、逐层几何一致性和帧级门控。
5. 将全量一致性改为流式邻域检查。
6. 接入 manifest、GUI 诊断和模型自动流程。
7. 运行 Dino、UAV 9 图 A/B；达标后再跑 UAV 444 图。

## 风险与控制

- 三级计算会增加 kernel 调用，但父层可收窄搜索区间，预计不会按层数线性增加总耗时。
- 过严门控会降低覆盖率，因此分别记录“原始覆盖、过滤覆盖、错误覆盖”，不能只追求点数。
- 场景误判必须允许用户覆盖，并把判定特征写入日志。
- 中间层保存会增加磁盘占用，默认只保存摘要和预览。
