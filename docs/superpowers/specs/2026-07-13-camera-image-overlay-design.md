# 三维模型“显示图像”修复设计

## 背景

当前 `CameraSceneWidget` 使用 QRhi/Vulkan 绘制点云和模型，但相机缩略图与“显示图像”功能由透明
`QPainter` 覆盖层完成。相机平面按 `_poses` 数组顺序绘制，没有使用观察深度，因此两个平面在屏幕上
重叠时，数组中靠后的照片会无条件覆盖靠前的照片。

现有“在前景中显示”和“在后景中显示”也只控制选中照片相对于相机缩略图、标签的绘制先后，并未控制
照片与三维模型之间的合成关系。这与 Metashape Model View 的“Show Images / Show In Front / Show
Behind / Lock Image”语义不一致。

## 目标行为

1. 普通相机缩略图保持位于各自相机平面，但按当前观察视角从远到近绘制；屏幕投影重叠时，靠近观察者
   的照片覆盖远处照片。
2. 开启“显示图像”后，根据当前三维观察方向自动选择方向最接近的有效已对齐照片。
3. 模型始终保留当前自由三维观察矩阵；所选照片作为其相机位置上的世界空间平面参与同一套投影，
   因此旋转、缩放和平移模型时，照片平面同步变化。
4. “在前景中显示”表示照片在三维模型之后合成并覆盖模型。
5. “在后景中显示”表示先绘制照片，再绘制三维模型，使模型覆盖照片。
6. “锁定图像”只固定当前照片，不锁定模型视角；解锁后恢复按观察方向自动选择。
7. 开启或关闭“显示图像”不改变自由三维视角、缩放和平移状态。
8. 照片异步加载不能阻塞 GUI 主线程。照片缺失或无法解码时继续显示模型，并输出包含照片路径的明确日志。

## 非目标

- 不修改 SfM、MVS、模型生成或相机标定数据。
- 不改变照片面板的选择规则和普通照片查看器。
- 不在本次修复中实现 Metashape 的立体显示硬件模式或双目立体对。
- 不重构现有点云、网格和手工剔除渲染流程。

## 方案比较

### 方案一：仅调整 QPainter 覆盖层

对普通照片做深度排序，并把当前照片铺满覆盖层。该方案改动最少，但透明覆盖层始终位于 QRhi 控件之上，
无法实现“照片在模型后面”的正确合成。

### 方案二：CPU 离屏截图后合成

读取 QRhi 输出后在 CPU 上与照片合成。该方案能够表达前后景，但每次交互都需要 GPU 到 CPU 回读，性能、
清晰度和跨平台稳定性均不理想。

### 方案三：QRhi 原生照片合成，普通缩略图进行深度排序

为当前照片增加纹理合成管线，在同一个 QRhi render pass 中根据模式于模型之前或之后绘制照片；普通相机
缩略图继续由覆盖层绘制，但先按视空间深度稳定排序。该方案能实现准确的照片/模型层级，且不扩大点云和
网格管线的改动范围，因此作为本次实现方案。

## 组件设计

### 相机显示数据

扩展三维视图使用的相机记录，使其除名称、路径、光心和旋转外，还包含：

- `focalX`、`focalY`
- `principalX`、`principalY`
- `imageWidth`、`imageHeight`
- 图像坐标轴方向

数据从项目中的 `xjw::Camera` 和影像元数据读取。图像尺寸缺失时可从异步加载结果补齐；内参无效时使用
当前 45° 透视投影作为回退，不能构造无效投影矩阵。

### 观察方向与照片选择

把“当前观察方向”和“相机拍摄方向”转换到统一世界坐标系，使用归一化向量点积作为主要评分。评分最高且
照片路径有效的相机成为当前叠加照片。点积接近时使用相机到场景中心的方向一致性作为稳定次序，最后使用
原始相机索引保证结果确定。

只有以下事件重新选择照片：

- 开启“显示图像”；
- 未锁定状态下旋转观察视角；
- 相机列表或高亮照片发生变化；
- 解除“锁定图像”。

锁定状态保存稳定的相机标识，不因照片面板选择或观察视角变化而切换。

### 世界空间照片平面

模型视图始终使用自由观察状态 `_viewRot`、`_zoomScale` 和 `_sceneOffsetPx`，显示图像不能替换或冻结
这套矩阵。选中的照片根据相机光心、右方向、上方向和影像宽高比构造四个世界坐标顶点，并与模型共用
同一套 MVP。这样照片保持在对应相机平面上，用户可以继续自由旋转模型，观察方向变化时再自动选择方向
最接近的有效照片。

相机内参仍作为后续精确投影和质量检查的数据保留，但本模式不把自由观察视图强制切换成某个相机的
标定视图。

### QRhi 合成顺序

新增一个带纹理采样的世界空间照片平面管线：

- 后景模式：照片通道 → 清理/保留所需深度状态 → 点云、网格和线框通道。
- 前景模式：点云、网格和线框通道 → 照片通道。

照片通道不写入三维深度；前景模式关闭深度测试并覆盖模型，后景模式在模型绘制之前执行。相机标签、局部
坐标轴和交互提示仍由透明覆盖层最后绘制，避免文字进入纹理合成管线。

异步加载完成前，后景模式使用现有白色清屏并继续显示模型；前景模式不绘制照片占位块，避免黑色矩形遮挡
模型。加载失败时保留该行为并记录路径和失败原因。

### 普通相机缩略图遮挡

绘制相机缩略图前计算每个相机中心在当前视图中的深度，生成索引列表并进行稳定的远到近排序，再绘制照片
平面。这样较近的平面最后绘制并覆盖较远平面。标签与高亮边框在平面绘制完成后单独绘制，避免标签被后续
照片无意义遮挡。

## 状态与交互

- “显示图像”关闭：自由三维观察，普通相机缩略图可独立显示。
- “显示图像”开启且未锁定：自由旋转保持可用，观察方向变化会选择方向最接近的照片。
- “显示图像”开启且锁定：只固定当前照片，自由旋转仍保持可用。
- 切换前景/后景：仅改变 QRhi 绘制顺序，不重新加载照片、不改变当前相机。
- 当前照片不可用：模型保持可交互，状态不会锁死；后续选择有效照片时可恢复显示。

## 测试设计

新增可直接单元测试的纯计算辅助逻辑，并按测试驱动顺序实现：

1. 两个共线相机平面无论输入数组顺序如何，排序结果都保证远处先绘制、近处后绘制。
2. 旋转自由观察方向后，选择与观察方向点积最大的有效相机。
3. 相同评分使用稳定次序，不在相邻帧间抖动。
4. 锁定后观察方向和高亮选择变化不会切换照片；解锁后重新自动选择。
5. 照片平面由相机光心、右方向、上方向和宽高比构造，并与模型使用相同 MVP。
6. 显示图像时 `sceneMatrices()` 仍只使用自由视图旋转，不依赖当前照片索引。
7. 前景模式的照片 draw call 位于模型 draw call 之后，后景模式位于模型之前。
8. 开启、锁定、解锁和关闭图像模式均不改写旋转、缩放和平移。
9. 现有菜单动作、异步照片加载和 QRhi/Vulkan 约束测试继续通过。

## 验收标准

- 截图所示同一直线上的相机照片重叠时，视觉上靠近观察者的照片始终覆盖远处照片。
- 在模型视图旋转到不同方向时，未锁定的“显示图像”会切换到对应方向的已对齐照片。
- 当前照片位于其相机世界平面上，并随自由三维视图同步旋转、缩放和平移。
- 前景模式可见照片覆盖模型；后景模式可见模型覆盖照片。
- 锁定、解锁、关闭显示图像的状态转换稳定，且始终保持当前自由视角。
- GUI 保持响应，照片加载失败不会崩溃或用不透明占位块遮住模型。
