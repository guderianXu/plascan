# PlaScan 单一连接点结果与 Metashape 工作区显示设计

## 目标

PlaScan 的连接点采用单一当前状态：项目中任意时刻只对外暴露一个当前连接点结果，新生成、稀释、清理、精修或平差结果成功后覆盖上一个结果。工作区按照 Metashape 的形式显示一个不可展开的“连接点（N个点）”资源节点。

删除连接点表示真实删除，不保留可回退的历史结果。覆盖和删除同时清理不再使用的生成文件，但不得误删新结果或其他工作流仍在引用的文件。

## 兼容范围

- 项目格式继续使用 `aerial_triangulation_results` 数组，避免立即破坏旧项目和现有查询接口。
- 新写入的项目元数据中，该数组最多包含一个当前结果。
- 打开包含多条历史结果的旧项目时，只选择从后向前第一个生成文件存在的有效结果用于工作区和后续处理。
- 打开旧项目本身不删除历史记录或文件，避免无提示的破坏性迁移。
- 下一次连接点结果成功写入时，将旧数组收敛为唯一的新记录，并清理旧记录文件。
- 用户显式删除连接点时，删除数组中全部遗留记录及其生成文件，成功后数组变为空。

## 架构

新增项目层连接点结果服务 `ProjectTiePointResultService`，放在 `src/gui/project/services`。该服务负责：

1. 从项目元数据中选择最新有效连接点结果。
2. 用已验证的新结果替换当前结果。
3. 收集旧结果关联的 PLY、JSON、报告和输出目录。
4. 保护新结果及其他项目记录仍引用的文件。
5. 安全清理不再使用的旧文件。
6. 显式删除项目中的全部连接点结果。

`ProjectManager` 作为服务入口，负责触发元数据写回、脏状态、工作区刷新、质量报告刷新和用户可见错误提示。`DataTreeWidget` 只消费已经选出的当前结果，不承担磁盘扫描、历史选择或文件删除。

现有 `appendAtResult()` 语义与新行为冲突。实施时应替换为明确的 `replaceTiePointResult()` 命名，并让所有空三、稀疏点处理和平差写回入口统一调用，避免未来流程重新追加历史记录。

## 当前结果选择

旧项目选择当前结果时，从 `aerial_triangulation_results` 末尾向前遍历，并要求：

- 记录是 JSON 对象。
- `files.sparse_cloud_xyz` 非空。
- 按项目根目录解析后的稀疏点云文件存在且是普通文件。

第一个满足条件的记录作为当前结果。若没有有效记录，工作区不显示连接点节点，依赖连接点的工作流继续使用现有缺失数据错误提示。

点数优先读取 `sparse_point_count`，其次读取 `point_count` 和 `quality.point_count`；均不可用时显示“连接点”，不伪造 `0个点`。

## 替换流程

连接点任务必须先在其输出位置完整写入新结果。服务收到新记录后按以下顺序执行：

1. 验证新稀疏点云文件存在，必要的 sidecar 路径非空且已写入。
2. 快照当前数组中全部旧记录及其关联文件。
3. 生成保护集合，至少包含新记录的全部文件、目录和其他项目结果仍引用的路径。
4. 将元数据中的 `aerial_triangulation_results` 原子替换为仅包含新记录的数组。
5. 标记项目已修改并刷新工作区、质量报告和依赖状态。
6. 删除旧记录中不在保护集合内的文件。
7. 仅当旧输出目录不包含受保护文件且确认属于项目生成目录时，才递归删除目录；否则只删除明确列出的旧文件并清理空目录。

若新结果验证失败，不修改旧元数据、不删除旧文件。若新元数据已成功写回但旧文件清理部分失败，新结果继续作为当前结果，同时记录警告并向用户列出残留路径；不得回滚到已经被替换的旧记录。

任务取消或运行失败不会调用替换服务，因此原有连接点保持不变。

## 删除流程

用户在唯一连接点节点上选择“删除数据”后，沿用现有确认交互，并执行：

1. 收集数组中所有当前和遗留连接点记录的生成文件。
2. 排除被其他项目结果引用的共享文件。
3. 尝试删除可安全删除的文件和专属输出目录。
4. 仅当所有必须删除的文件均成功处理后，清空 `aerial_triangulation_results`。
5. 刷新工作区、属性面板、质量报告和重建动作状态。

若文件被占用、权限不足或目录不安全，保留项目记录，显示失败路径，不报告删除成功。删除后没有历史结果回退，连接点节点直接消失。

## 工作区显示

工作区仅创建一个顶层资源叶节点：

```text
连接点（2,314个点）
```

显示规则：

- 使用现有四点连接点图标。
- 节点不可展开，不显示展开箭头。
- 不显示 `#0`、操作名称、源结果编号、输出目录或“当前”等内部信息。
- 点数使用本地化千位分隔符并带“个点”。
- 节点直接保存当前稀疏点云路径和 `generated` 存储类型。
- 选择、激活、打开、在文件管理器中显示、属性和删除操作均直接作用于该节点。
- 无有效当前结果时不显示节点。

照片、模型、稠密点云、DEM、正射影像和报告的树结构不在本次修改范围内。

## 错误与安全边界

- 所有路径先按项目根目录规范化，并使用平台原生文件接口处理中文路径。
- 不删除项目目录外的目录树；外部文件只能在明确属于本次生成记录且通过安全校验时删除。
- 新旧结果共用同一输出目录时，禁止直接递归删除该目录。
- 文件保护以规范化绝对路径比较，Windows 下按不区分大小写处理。
- 元数据写回失败时不执行旧文件清理。
- 删除失败必须保留足够元数据以便用户重试。

## 测试

使用 GTest 覆盖：

1. 多条旧记录中选择最新且文件存在的结果。
2. 最新记录文件缺失时回退到前一个有效结果。
3. 新结果替换后数组只保留一条记录。
4. 新结果验证失败时旧结果和旧文件保持不变。
5. 新旧结果共用目录时不删除新文件或共享目录。
6. 覆盖后安全删除不再引用的旧 PLY、JSON 和专属目录。
7. 显式删除成功后数组为空且工作区节点消失。
8. 删除部分失败时元数据保留并返回具体失败路径。
9. `DataTreeWidget` 对多记录旧元数据只显示一个不可展开的连接点叶节点。
10. 节点文本为本地化的 `连接点（2,314个点）`，其资源路径指向当前结果。
11. 点击、激活和右键删除信号使用当前连接点路径及“连接点”分区。

验证范围包括相关 GTest、`ctest` 过滤运行、Release GUI 构建，以及打开旧项目和生成新连接点后的人工工作区检查。

## 非目标

- 不把其他结果数组改成单对象格式。
- 不删除用户仅打开但未修改的旧项目历史文件。
- 不为连接点增加版本浏览、恢复或历史面板。
- 不改变连接点算法参数、SfM 计算逻辑或点云文件格式。
- 不修改其他工作区资源的多结果显示策略。
