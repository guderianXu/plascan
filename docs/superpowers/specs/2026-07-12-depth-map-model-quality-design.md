# 深度图模型质量优化设计

## 背景

Dino 16 图项目的稀疏重建已注册全部影像，平均重投影误差约 0.50 px，但深度图呈现大块近常深度区域和局部色斑，最终模型形成低面数刺团。当前链路还存在“深度图源实际复用临时密集点云，再进入简化 Poisson”的语义偏差。

## 已确认根因

1. CUDA PatchMatch 的多源代价只平均 NCC 大于阈值的源图。一张源图出现偶然高相关时，其他源图的失败不会惩罚该假设，导致错误深度获得高置信度。
2. 精细层使用最近邻放大的粗层深度作为满覆盖 hint，并在覆盖率高时减少迭代，粗层错误容易被锁定。
3. 单独保存深度图时不会执行融合前后处理；后续从磁盘融合只做置信度阈值，局部突刺和小连通域过滤没有复用。
4. 模型自动流水线对 32 帧以内项目把最少一致观测数降到 2，削弱了 16 图环拍项目本可利用的多视约束。
5. 融合点云法线方向不稳定，模型阶段逐点按质心翻转法线会破坏凹面局部一致性。
6. 当前 PlaPoint Poisson 为轻量 Poisson-style 实现，最大深度 8；界面目标面数只参与简化，不能增加原始网格细节。

## 设计

### CUDA PatchMatch

- 多源 NCC 使用“至少两源支持”的鲁棒聚合。两源场景必须同时支持；三源及以上允许遮挡，但至少需要半数以上有效支持。
- 置信度由鲁棒聚合结果生成，不再因单源偶然高 NCC 接近 1。
- 精细层始终执行用户请求的完整迭代数。粗层结果仍作初始化，但不能因为 hint 覆盖率高而减少搜索。
- 保留现有 CUDA checkerboard sweep 和 GPU 图像缓存，不引入 CPU 像素回退。

### 深度后处理与流式融合

- 将置信度过滤、局部深度突刺过滤和小连通域过滤收敛为可复用函数。
- 内存生成与磁盘加载融合使用同一后处理语义，并记录真实统计。
- 模型流水线不再因为帧数小于等于 32 自动降为双视；只有显式预览模式可启用低产出回退。
- 流式融合继续按帧窗口执行，像素反投影和一致性检查沿用多线程 worker。

### 网格输入质量

- 对闭合物体保留局部法线关系，只做邻域一致传播后再决定全局朝向，避免逐点质心翻转凹面。
- Poisson 前报告预处理点数、法线修复数和方向翻转数。
- 本批次不引入 Open3D/PCL 等新依赖；若轻量 Poisson 仍限制细节，后续单独实现 TSDF/Screened Poisson，不与本次深度质量修复混在一起。

## 性能约束

- PatchMatch 仍全部在 CUDA 上计算，多源聚合只增加固定长度局部数组和少量比较。
- 深度后处理按帧执行，流式融合沿用现有线程池，不常驻全部深度图。
- 法线一致化使用 PlaPoint KDTree；CPU 查询并行化，避免 GPU 暴力 KNN 在大点云上的平方复杂度。

## 验收

- 单元测试覆盖多源聚合、完整精细迭代、磁盘深度后处理和模型流水线最少一致视图数。
- Dino 16 图重新生成深度图、密集点云和模型。
- 对比旧结果：深度图相邻像素相对跳变、点云半径 P99/最大值、有效法线比例、网格顶点/面数和连通分量。
- GUI 与 CLI 使用同一核心配置，Windows CUDA 主构建通过。
