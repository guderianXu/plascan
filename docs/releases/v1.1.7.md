# PlaScan v1.1.7

发布日期：2026-08-10

## 新增

- Windows CUDA 安装包内置 U2Net、LightGlue 与 LoMa-R 便携 ONNX 模型。LoMa-R 包含共享特征模型、
  动态匹配模型和 K1024/K2048/K3840 三份 manifest，安装后无需手工指定权重目录。
- 图像匹配继续支持 LightGlue 与 LoMa-R；目标电脑首次使用时由 C++ TensorRT Builder 构建与当前
  GPU/TensorRT 兼容的 engine，并写入用户模型缓存。
- 本版本包含 v1.1.6 之后进入 `main` 的摄影测量、MVS、地形产品、小天体全局产品和 GUI 工作流更新。

## 优化

- 公共模型查找顺序统一为：`PLASCAN_MODEL_DIR`、源码开发资源、用户模型目录、安装根
  `resources/models` 与兼容缓存。安装态不会误命中编译机源码目录，空环境目录仍会回退到内置模型。
- LoMa-R 自动选择只为最终 K 档构建 engine，同规格模型保持搜索目录优先级，避免首次使用重复构建。
- Windows 正式打包使用 `lzma2/ultra64`、solid compression 和默认 4 个 LZMA2 block threads；日常
  修改使用 `windows-package-smoke` 增量更新未压缩安装树，不重复执行完整压缩。
- Windows OpenCV 发布依赖启用 CUDA、cuDNN 和 DNN CUDA，U2Net 可直接使用 GPU 推理。

## 修复

- 修复设置了空的 `PLASCAN_MODEL_DIR` 后匹配模块不再回退安装内置模型的问题。
- 修复安装版仍可能搜索编译期源码模型目录、掩盖漏打包资源的问题。
- 修复同一 K 档 LoMa-R 按绝对路径字典序选择、破坏环境目录优先级的问题。
- Windows CPack 对 7 个模型执行固定长度与 SHA-256 校验；Windows/Linux staging 均递归禁止任何本机
  TensorRT `.engine` 进入安装包。

## 已知问题

- LoMa-R 首次使用需要针对目标 GPU/TensorRT 构建 feature 与 matcher engine，首次运行会明显慢于后续
  缓存命中；安装包不提供不可移植的预生成 `.engine`。
- Windows CUDA 安装包包含多架构 TensorRT 运行库与 1,591,534,367 字节模型（约 1.59 GB / 1.48 GiB），
  下载和安装体积较大。
- `PatchMatchCudaBenchmarkTest.CompareParallelAndLegacySweepAfterWarmup` 仍为 disabled benchmark。

## Windows 下载说明

GitHub Release 必须同时下载并放在同一目录：

- `plascan-1.1.7-Windows-AMD64.exe`
- `plascan-1.1.7-Windows-AMD64-1.bin`
- `plascan-1.1.7-Windows-AMD64-2.bin`
- `plascan-1.1.7-Windows-AMD64-INNOSETUP.sha256`

双击 `.exe` 安装；缺少任一 `.bin` 都无法完成安装。可先按 SHA-256 清单校验全部文件。
