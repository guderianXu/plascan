# PlaScan v1.1.2

发布日期：2026-06-17

补充更新：2026-06-18。新增 MVS 深度图内存自适应保护、快速二进制深度产物保存和 GUI CUDA 帧流水线自适应，代码已进入 `main`；既有 `v1.1.2` tag 未强制重写。

## 新增

- 增加 `docs/design/LASER_PHOTOGRAMMETRY_DATASETS.md`，整理后续激光点 / LiDAR 参与摄影测量处理所需的数据集候选、许可风险、fixture 结构、数据字段和实现路径。
- `testData/download_photogrammetry_testdata.py` 增加 `workflow_tags` 元数据和 `--workflow-tag` 参数，可按 `ba_constraint_candidate`、`lidar_fusion_validation` 等用途筛选 MUN-FRL、H3D、NTU VIRAL、KITTI Raw 等 LiDAR 相邻数据集。

## 优化

- MVS 可见性缓存从串行写共享容器改为 OpenMP worker-local shard，再统一合并 `visiblePointIndices`、pair common count 和 visibility bitset，降低大稀疏点云加载后的 CPU 准备时间。
- 每帧预缓存选中源帧共享的稀疏点，深度范围、hint、support mask 复用同一组点，减少重复共视过滤。
- 源帧打分先按共视点数排序；当当前 top 源帧已经从共视点数上界证明不会被后续候选超过时，提前停止三角角度采样。
- 稀疏 hint 投影改为单次可见点遍历，深度 IQR 分位采样有上限，避免每帧对数十万稀疏点重复排序和重复投影。
- 粗层 hint 使用 OpenCV distance transform 进行限距离传播；精层只叠加稀疏 seed，避免错误深度 hint 全图传播影响 CUDA PatchMatch。
- 稀疏支撑掩码改为按精层 PatchMatch 工作尺寸生成，并作为软先验缩放置信度，不再硬裁剪深度。
- dense refine 对大规模点云增加输入上限、内联过滤上限和第二轮 SOR 跳过路径，减少 GUI/CLI 在百万级点云上的卡顿风险。
- CUDA 灰度图路径避免重复 reference resize，并保留灰度图 GPU 缓存命中/未命中统计，用于诊断 GPU 利用率不连续。
- MVS 深度图缓存策略改为自适应：启动时估算所有 full-res `depth + confidence` Mat 的常驻内存需求，结合系统物理内存、可用内存和保留内存决定是否继续缓存；内存充足时保留空间换时间，内存不足时自动切换为流式保存。
- 深度图保存队列增加有界积压控制，限制后台预览/中间结果保存任务持有的 full-res 深度帧数量，降低大图保存落后时的内存峰值。
- 深度图原始产物改用 PlaScan 二进制 `.bin` 保存 depth/confidence，替代 OpenCV `.yml.gz` 文本压缩写入，减少每帧 CPU/IO 保存停顿；正式深度缓存只接受 `.bin` 格式。
- 深度图预览 PNG 默认限制最长边 2048，避免保存全尺寸 6000x4000 伪彩图阻塞后台保存队列。
- GUI 手动深度估计的 CUDA frame workers 改为自适应，线程数足够时默认使用 2 帧流水线，提高 GPU 任务连续性。

## 修复

- 修复局部红色深度噪点缺少后处理保护的问题，增加局部深度离群过滤和每阶段耗时日志。
- 修复稀疏支撑过滤过硬导致深度图有效区域被大量清空的风险。
- 修复 dense refine 在大点云上连续执行昂贵过滤导致的交互阻塞风险。
- 修复大规模 MVS 深度估计无条件缓存每帧 full-res 深度/置信图导致内存持续增长的问题；运行时检测到可用内存低于保护阈值时，会先释放已缓存深度图并切换流式保存，避免等到 OpenCV 分配失败后崩溃。
- 修复单次内存融合在系统内存明显不足时仍继续排队深度估计的风险；现在会提前提示用户先生成深度图，再单独运行深度图融合。
