# PlaScan v1.1.3

发布日期：2026-06-18

## 新增

- 增加 `src/core/lidar` 模块，用于 LiDAR / 激光点点到面约束。模块支持读取 ASCII / binary little-endian PLY，筛选 `x/y/z + normal_x/normal_y/normal_z` 平面样本，按曲率和体素进行采样，并为 BA tracks 查询最近 LiDAR 平面。
- `BundleAdjust` 支持可选 LiDAR 点到面软约束，输出 LiDAR 约束数量、优化前后 RMS、median 和关联统计。
- 新增 `bundle_adjust_cli`，可从 `.plascan` 项目构建 BA 输入并执行 headless BA。CLI 支持 `--laser-cloud`、`--laser-max-distance`、`--laser-weight`、`--laser-huber-delta`、`--ab-compare`、`--dry-run` 和 `--export-eval-plot`。
- `feature_match_cli` 在传统 BF/FLANN 匹配输出 `.match` 的同时写入 `.match.json` sidecar，记录匹配点坐标、特征索引、匹配分数、影像 token 和特征文件路径，供后续多视 track 构建。
- GUI 光束法平差对话框新增 LiDAR 约束设置，ProjectManager 与 BundleAdjustService 已能把 LiDAR 参数传递到核心 BA。
- 新增 MUN-FRL LiDAR BA 测试数据工具：
  - `testData/validate_lidar_ba_inputs.py`
  - `testData/prepare_lidar_ba_ab_benchmark.py`
  - `testData/estimate_lidar_normals.py`
  - `testData/prepare_mun_frl_lidar_ba_project.py`
  - `testData/compare_lidar_ba_ab_results.py`

## 优化

- `prepare_mun_frl_lidar_ba_project.py` 支持 `--tf-static --camera-frame --body-frame`，将 ROS 静态外参和 odometry 位姿合成为 PlaScan 的 camera-to-world `R/C`。
- A-B 比较报告增加共同有效 track RMS、相机中心漂移、旋转漂移、LiDAR RMS/median 和约束数量，避免只用全局重投影 RMS 评价激光约束效果。
- `testData/README.md` 记录 MUN-FRL lighthouse 从 benchmark window、匹配 sidecar、LiDAR normal 估计、`.plascan` 打包到 BA A-B 对比的命令链。
- `docs/PROJECT_ARCHITECTURE.md` 更新 LiDAR core 模块、`bundle_adjust_cli` 和 feature match sidecar 说明。

## 修复

- `bundle_adjust_cli` 默认关闭评估图导出，避免 headless 环境因 GUI/绘图依赖中断；需要图表时可显式加 `--export-eval-plot`。
- 对 MUN-FRL 样例 PLY 法线全为 0 的情况提供法线估计预处理，解决 LiDAR constraint map 无有效平面样本的问题。

## 验证

本地 Windows CUDA 验证：

```powershell
python -m unittest tests.test_prepare_mun_frl_lidar_ba_project tests.test_compare_lidar_ba_ab_results tests.test_estimate_lidar_normals tests.test_bundle_adjust_cli tests.test_feature_match_cli_sidecar
$env:PLASCAN_FEATURE_MATCH_CLI='E:\code\plascan\build\windows-vcpkg-cuda-release\bin\feature_match_cli.exe'
$env:PLASCAN_BUNDLE_ADJUST_CLI='E:\code\plascan\build\windows-vcpkg-cuda-release\bin\bundle_adjust_cli.exe'
python -m unittest tests.test_bundle_adjust_cli tests.test_feature_match_cli_sidecar tests.test_prepare_mun_frl_lidar_ba_project tests.test_compare_lidar_ba_ab_results
python -m py_compile testData\prepare_mun_frl_lidar_ba_project.py testData\compare_lidar_ba_ab_results.py testData\estimate_lidar_normals.py
ctest --test-dir build\windows-vcpkg-cuda-release --output-on-failure -R "lidar|Lidar|Laser|BundleAdjustCliTest|FeatureMatchCliSidecarTest|PrepareMunFrlLidarBaProjectTest|CompareLidarBaAbResultsTest|EstimateLidarNormalsTest"
```

结果：

- Python 工具/CLI 单测通过；未设置 CLI 环境变量时相关 CLI 用例跳过，设置环境变量后 10/10 通过。
- 脚本语法检查通过。
- LiDAR / BA / CLI / 数据准备相关 CTest 通过，19/19。
- MUN-FRL lighthouse 20 张图窗口生成 `mun_frl_lidar_ba_tf.plascan`，dry-run 输入为 `cameras=20 tracks=3689 sidecar_v2_pairs=230822 multiview_tracks=3689`。
- MUN-FRL 诊断：
  - `camera_init -> lio_body` 加 `camera -> imu_link` 反向外参：影像-only BA 基线约 `0.533 px`，但 3-5 m LiDAR 约束使 LiDAR RMS 增大。
  - `camera_init -> lio_body` 加 `camera -> velodyne` 反向外参：LiDAR RMS 可下降，但影像-only BA 基线约 `1.126 px`。

## 已知问题

- MUN-FRL `lio_body` 与 `imu_link` / `velodyne` / `camera` 的准确 frame 语义仍需进一步核实；本版本证明了 LiDAR 约束接入、A-B 管线和诊断工具可用，但不宣称该样例已经带来可靠精度提升。
- 本版本没有重新跑 agisoft aerial GCP 444 张完整 MVS/mesh/DEM/DOM 长时流水线。
- CI 仍暂时排除历史已知失败 `TerrainDemDomTest.TerrainPipelineGeneratesDemDomFromDirectory`，该测试可能出现 `dom_png not found`。
- GitHub Actions `build-test` 是远端门禁；`v1.1.3` tag 推送后以 Actions 结果为准。
